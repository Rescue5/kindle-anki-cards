# Plan: M1 ranking, M3a newcomers, M2 two screens

Implementation plan agreed by the lead from the architect's blueprint
(2026-11-19) and trimmed by `product-skeptic`. Scope is in `PRODUCT.md`; this
file says how. Lanes own files; contracts change only through the lead.

## Decisions

1. **Ranking is computed live** in the bridge on every response from persisted
   inputs (`kindle_vocab_app/ranking.py`, pure). No cache table. Gate: a test
   ranking 3,000 lexemes in under 150 ms. Fallback only if the gate fails: a
   `rankings` table keyed by `lexeme_id` with input hash + ranking version.
2. **User data lives in new tables keyed by `lexeme_id`, without FK**, so it
   survives `_replace_catalog` (which deletes and re-inserts `lexemes`). Each
   row also stores `language` + `canonical_key` as a re-link hint; the catalog
   save ends with a re-link step; nothing is ever deleted from user tables.
3. **User writes go straight to their own tables** in one small transaction,
   never through `save_catalog` (avoids the load-mutate-save race with
   `process_queue`).
4. **Export history is append-only** (`export_runs` + `export_items`) and the
   single source of export state. Obsidian keeps its reconciliation row.
5. **One eligibility function** `export_policy.is_exportable`: decision
   `learn`, or no decision and shelf `worth`; `known|skip|junk` never. It
   replaces the five copies of "accepted + score 3..10"
   (`anki_export.py:107`, `enrichment.py:118`, `library_repository.py:973`,
   `tauri_bridge.py:777`, `obsidian_sync.py:83`).
6. **One card resolver** `card_fields.resolve`: translation edited > LLM >
   dictionary; example chosen occurrence > longest context. Used by every
   writer and by the payload.
7. **"New since last time" reuses `lexemes.freshness`**: `merge_kindle`
   demotes `new` to `known` only when the sync actually adds a lexeme
   (`vocab_cache.py:106`), so an empty second sync no longer erases the batch.
8. **Short list**: the export "new" scope takes the top N `worth` words by
   rank (setting `export_batch_size`, default 20); the rest stay for later.
9. **Again after export**: a lexeme with a lookup after its last export (or a
   card edit after it) and no `known|skip|junk` decision. Re-export keeps the
   Anki GUID (`anki_export.py:216`) and adds the tag `повтор`.
10. **Reading book** is inferred: books with a lookup in the last 14–30 days.
    No `book_state` table, no pages, no per-10-pages, no Progress/Book screens.
11. **Errors**: user-facing Russian `ValueError` text passes through; anything
    else becomes «Не получилось. Подробности в журнале» with the traceback in
    the log. The `{ok:false,error}` shape stays, so Rust is unchanged.

## Schema v4

Migration runner replaces the idempotent `_initialize`
(`library_repository.py:476`): read the version; if `< 4` and the file had
data, copy it to `.app-data/backups/kindle_cards.v3.<utc>.sqlite3` (keep 3);
`BEGIN IMMEDIATE`, re-read the version, run statements one by one (not
`executescript`), write the version row, commit; on failure roll back and raise
«Не удалось обновить библиотеку; копия сохранена».

```sql
CREATE TABLE word_decisions(
  lexeme_id TEXT PRIMARY KEY, language TEXT NOT NULL, canonical_key TEXT NOT NULL,
  decision TEXT NOT NULL CHECK(decision IN ('known','learn','skip','junk')),
  decided_at TEXT NOT NULL,
  shelf_at TEXT NOT NULL DEFAULT '', score_at REAL, ranking_version TEXT NOT NULL DEFAULT ''
);
CREATE INDEX idx_word_decisions_key ON word_decisions(language, canonical_key);

CREATE TABLE card_edits(
  lexeme_id TEXT PRIMARY KEY, language TEXT NOT NULL, canonical_key TEXT NOT NULL,
  meaning_ru TEXT, example_occurrence_id TEXT,
  example_context TEXT NOT NULL DEFAULT '', example_form TEXT NOT NULL DEFAULT '',
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_card_edits_key ON card_edits(language, canonical_key);

CREATE TABLE export_runs(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  destination TEXT NOT NULL CHECK(destination IN ('anki','csv','obsidian')),
  scope TEXT NOT NULL CHECK(scope IN ('new','again','migrated')),
  created_at TEXT NOT NULL, word_count INTEGER NOT NULL, path TEXT NOT NULL DEFAULT ''
);
CREATE TABLE export_items(
  run_id INTEGER NOT NULL REFERENCES export_runs(id) ON DELETE CASCADE,
  lexeme_id TEXT NOT NULL, language TEXT NOT NULL, canonical_key TEXT NOT NULL,
  is_repeat INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(run_id, lexeme_id)
);
CREATE INDEX idx_export_items_lexeme ON export_items(lexeme_id);
```

Data migration: backfill `export_runs(scope='migrated')` + items from
`destinations` rows (anki/quizlet `state='exported'` → `anki`/`csv`; obsidian
`synced`); copy `review_cards` into `legacy_review_cards` (no FK, read by
nothing, dropped one release later) and drop `review_cards`; leave
`analyses.payload_json` untouched (CLI audit). Seed no decisions.

`load_catalog` (`:53`) becomes bulk queries (today ~4 queries per lexeme).

## Bridge contract

Lexeme payload adds:

```json
{ "ranking": {"score":0.82, "shelf":"worth|not_worth|disputed|junk|known", "rank":3,
              "lean":"learn|skip|junk|null",
              "reasons":[{"code":"repeat_lookups","text":"искали 3 раза","weight":3}],
              "version":"r2"},
  "decision": {"value":"known|learn|skip|junk", "decided_at":"iso"},
  "card": {"meaning_ru":"...", "meaning_source":"edited|llm|dictionary|none",
           "example_occurrence_id":"...", "edited":true},
  "export": {"state":"exported|not_exported", "last_exported_at":"iso",
             "again":true, "lookups_after":2},
  "is_new": true }
```

`ranking` is `null` for unprocessed lexemes; `rank` is 1-based inside the shelf.
Library responses add `rankingVersion`, `shelves` counts, `newBatch`
(count, worth, not_worth, disputed, junk) and `again` (count).

Actions:

- `set_decision {lexeme_id, decision|null}` → `{entry, shelves, newBatch, disputed, again}`.
- `save_card_edit {lexeme_id, meaning_ru?, example_occurrence_id?}` → `{entry}`;
  errors «Перевод длиннее 200 символов», «Пример не относится к этому слову».
- `export_preview {}` → `{destination, new:{count, ids}, again:{count, ids}, blockedReason}`.
- `export_words {job_id, scope:"new"|"again", ids?}` → `{destination, run_id, exported, path, pushed, message}`;
  destination comes from settings (`export_destination`: `anki|csv|obsidian`);
  a run is recorded only after the file exists / push / vault verify succeeded.
- Removed: `load_review`, `rate_review`, `export`, `export_apkg`, `push_anki`,
  `sync_obsidian` (folded into `export_words`).
- Unchanged: `connector_status`, `load_demo` (now ranked), `load_obsidian`,
  settings (adds `export_destination`, `export_batch_size`), processing, LLM,
  `open_path`.

## Ranking contract answers (for `ranking.py`)

- Reason `weight` sign is what the UI uses (>0 for, <0 against); codes are a
  fixed exported list `REASON_CODES`; `RANKING_VERSION` constant.
- `Ranking.lean` added for disputed words (suggested answer).
- `proper_noun` comes from analysis warnings/heuristic chosen by the ranking
  lane and documented next to `WordFacts`.
- «учтёт для похожих слов» is not promised until a learner on decisions exists.
- Built (2026-11-19): `score` is always `sigmoid(bias + Σ reason weights)`; a
  reader decision is a zero-weight reason that only sets the shelf, so lists
  sort by shelf first, then score. `WordFacts.decided_at` lets a «Знаю» word
  return to the model when it is looked up after the decision (reason
  `known_again`). The bridge passes `now` = time of the latest lookup in the
  library, so a pause in reading does not empty «Стоит учить».

## Risks

Migration on real libraries (backup + transaction + test on a copy);
orphaned user rows after canonical merges (kept and logged, never deleted);
payload size (bulk queries, single-entry responses for writes); concurrent
bridge processes (direct small writes, busy timeout).
