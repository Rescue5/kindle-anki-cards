# Книжный приоритет RP-V2 в Kindle Cards

Оценка отвечает на вопрос читателя «Какое из сохранённых слов я с большей вероятностью встречу в следующем современном англоязычном романе?». Даже один поиск даёт основание показать читателю книжную оценку. Личная частота обращений, дата и решение «Учить» в её формулу не входят.

## Выбор модели

Для каждого автора берём долю его романов, содержащих лемму хотя бы один раз. Затем усредняем эти доли по авторам. Десять употреблений в одной книге дают тот же вклад, что одно. Автор с десятью романами получает такой же суммарный вес, как автор с одним. Таблица построена по 771 обучающему роману 636 авторов из CONLIT. [Описание корпуса Эндрю Пайпера](https://doi.org/10.5334/johd.88) · [Использованная версия данных](https://doi.org/10.6084/m9.figshare.21166171.v1).

В отложенной части исследования было 393 романа 315 авторов. Показатель ниже — доля слов из первой пятёрки, которые встретились в следующем романе.

| Порядок | Доля |
| --- | ---: |
| Книжный охват с равным весом авторов | 77,10% |
| Книжный охват с равным весом книг | 77,11% |
| Прежний исследовательский вариант (`prior_original`) | 69,13% |
| Общая частота английского | 64,42% |

Равные веса авторов позволяют избежать перевеса плодовитых писателей. В измерении обе версии книжного охвата практически эквивалентны. Охват показывает возможность применить слово снова. Прирост понимания текста после изучения конкретного значения у русскоязычных взрослых ещё предстоит измерить. Корпус ограничен книгами 2001–2016 годов и представленными в нём жанрами.

Авторы сравнили 13 способов прогнозировать участие слов в сюжетных ответах. На 170 полных рассказах добавление сюжетной модели к частоте в пересказах дало +0,004 попадания на 100 рассказов с 95%-ным интервалом от −0,053 до +0,065. Поэтому продукт использует колонку `coverage` без дополнительного сюжетного коэффициента. Исходные [отчёт](../../.app-data/openresearch/rp-v2/report.md), [таблица сравнения](../../.app-data/openresearch/rp-v2/prior-study/comparison.csv) и [реестр данных и условий](../../.app-data/openresearch/rp-v2/data-register.md) доступны после распаковки комплекта.

## Что видит читатель

Каталог и предпросмотр полной библиотеки показывают слова с известным охватом по убыванию точной доли. Объяснение в строке и в карточке показывает долю романов в выборке с поправкой на вес авторов. Решение читателя и история выгрузок определяют допуск в подборку новых слов. Внутри этой подборки действует тот же книжный порядок. Полный экспорт сохраняет выбранные уровни и порядок показанного списка.

| Слово | Охват | Уровень |
| --- | ---: | ---: |
| borrow | 72,32% | 2 |
| sword | 45,55% | 3 |
| harpoon | 4,64% | 7 |
| give up | нет измерения для целого выражения | 6, предварительно |
| 00:17 | запись без букв | 10, проверить |

Интерфейс разбивает непрерывный балл на девять уровней. Включительные нижние границы уровней 1–8 составляют 75%, 50%, одну треть, 20%, 10%, 5%, 2% и 0,5%. Остальной измеренный диапазон, включая измеренный ноль, получает 9. Эти границы выбраны для интерфейса. После измеренных слов идут предварительные оценки, в конце — записи уровня 10. Совпадения точных баллов разрешаются постоянным идентификатором. Частоте отдельного слова внутри выражения приложение не присваивает вес всего выражения.

## Модель и воспроизводимость

Из корня проекта с активным окружением импортируйте файл из комплекта исследования. Импортёр проверяет SHA-256 исходной модели и атомарно создаёт компактную SQLite-таблицу. Копирование личного словаря и повторная обработка старых слов для этого не требуются.

```powershell
python -m scripts.import_openresearch_coverage .app-data/openresearch/rp-v2/models/ranker.json.gz --workspace .
```

Та же команда принимает `research-kit-v2.zip` вместо gzip. SHA-256 архива — `8abd038d19116e52feceeb821ae336c849c4dbe6fca0169feaf4f507475cd096`, исходной таблицы — `d75e5ba0b3cd3a21f449955b627e48f9344b95a9ad1694f2d2c7c4956f24e686`. В ней 184 933 словарных ключа, у 181 670 есть измерение. Отдельная таблица хранит 1 885 сопоставлений форм. Рабочий файл — `.app-data/models/rp-v2-coverage.sqlite`. В частной переносной сборке копия лежит в `bridge/models/`. Библиотеки без доступного файла продолжают работать с прежней оценкой. Исследование фиксирует расхождение условий CONLIT между карточкой набора и статьёй. Модель подготовлена для локальной работы и внутренней сборки.

Для независимого сравнения слов и точных выражений исходный CLI использует общую шкалу 422 пересказов. В этом режиме `give up` встречается в 11 пересказах, `sword` — в 10, `borrow` и `come across` — в трёх каждое. Эти величины не смешиваются с охватом современных романов.

```powershell
python -X utf8 .app-data/openresearch/rp-v2/rank.py borrow sword harpoon
python -X utf8 .app-data/openresearch/rp-v2/rank.py --method summary_df "give up" sword borrow "come across"
python -m kindle_vocab_app.ranking_eval --coverage-workspace . --out .app-data/openresearch-integration-eval/after
```

Последняя команда проверяет другой исход — повторное обращение читателя к словарю в течение 42 дней. При локальном сравнении в двух общих временных срезах среди первых 50 слов доля повторных поисков составила 5% у RP-V2 и 32% у прежней персональной модели. AUC составила 0,589 и 0,642 соответственно. Это один профиль и короткая история. Результат сохраняет основания для отдельной персональной подборки, если продукту понадобится предсказывать именно повторные поиски.
